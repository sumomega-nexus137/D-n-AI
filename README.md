# D-n-AI — агроскан по фото

**AgriTech AI Hackathon, Трек 3 — компьютерное зрение в агрономии.**

Фермер фотографирует пробу зерна или больной лист на обычный телефон и за
несколько секунд получает не «вероятность 0.87», а ответ, с которым можно
идти на элеватор: доли зёрен по категориям, предварительный класс, цену в
тенге за тонну и конкретные шаги — что сделать с партией и сколько это
принесёт.

Два входа в одну и ту же систему: **сайт** и **Telegram-бот**.

---

## Что он делает

### Модуль 1 — качество зерна пшеницы (главный)

По фото пробы, разложенной тонким слоем:

- **доли по категориям:** целое здоровое / битое-повреждённое /
  щуплое-мелкое / проросшее / сорная примесь;
- **предварительный класс** зерна по упрощённым нормам сорной и зерновой
  примеси;
- **цена** в тенге за тонну и вилка «от и до»;
- **что делать:** просеять, дочистить, проверить склад — с расчётом, на
  сколько тенге за тонну поднимется партия после очистки;
- честная оговорка: если зёрен на фото мало, сервис прямо пишет, что оценка
  ориентировочная.

### Модуль 2 — болезни, вредители и сорняки

По фото листа или растения: диагноз (24 класса), что это такое, что делать,
срочность и две альтернативные версии с уверенностью. При низкой уверенности
сервис так и говорит, а не выдаёт случайный класс за факт.

### Голосовые сообщения в Telegram

Вопрос голосом на казахском или русском уходит напрямую в Gemini Flash —
он же распознаёт речь, он же отвечает. Своего распознавания речи в проекте
нет специально: незачем.

## Результаты

- **Модуль 1 (качество зерна):** accuracy 98.84%, macro-F1 0.9884 на
  held-out тесте (5 классов).
- **Модуль 2 (болезни/вредители/сорняки):** accuracy 85.71%, macro-F1 0.854
  на held-out тесте (24 класса).
- **Сравнение с Gemini (zero-shot, без дообучения):** наша специализированная
  модель точнее определяет повреждённость/битость зерна — ключевую метрику
  задачи 3.3 — и не уступает Gemini в распознавании болезней листа по фото.

Held-out тест — **целиком отдельный источник данных**, а не перемешанная
выборка: модель на нём не видела ни одного кадра. Подробности обучения —
[`docs/TRAINING_RESULTS.md`](docs/TRAINING_RESULTS.md), сегментация —
[`docs/SEGMENTATION.md`](docs/SEGMENTATION.md), проверка на реальных фото с
телефона — [`docs/REAL_WORLD_TEST.md`](docs/REAL_WORLD_TEST.md).

## Архитектура

```
фото
 └─ Модуль 1: OpenCV-сегментация зёрен  (классический метод, без нейросети)
     │   Otsu по яркости и насыщенности → выбор маски по текстуре (лапласиан)
     │   → морфология → watershed по локальным максимумам яркости
     ↓
 замороженный DINOv2 ViT-S/14  (готовые веса, без дообучения)
     ↓  эмбеддинг 384 измерения
 голова-классификатор LogisticRegression  ← единственное, что обучается
     ↓
 агрегация: доли категорий → класс зерна → цена → рекомендации
```

Почему так, а не «обучим свой детектор»: за трое суток своя сеть на таком
объёме данных даёт хуже, чем линейная голова поверх честно предобученных
признаков DINOv2 — и это воспроизводимо. Обучается ровно один слой, веса
головы лежат в репозитории (`models/`, 90 КБ), веса DINOv2 скачиваются
автоматически при первом запуске.

**Ответ укладывается в 5 секунд** на бесплатном CPU-хостинге: зёрна
прогоняются через модель, пока не исчерпан бюджет времени
(`INFERENCE_TIME_BUDGET_S`), и сервис честно пишет в ответе, сколько зёрен
из найденных он успел разобрать.

## Запуск локально

Нужны Python 3.11+ и Node 20+.

### 1. Backend

```bash
git clone https://github.com/sumomega-nexus137/D-n-AI
cd D-n-AI
python -m venv .venv && source .venv/bin/activate
pip install -r backend/requirements.txt

cp .env.example .env        # ключи можно не заполнять: API работает без них
uvicorn backend.app.main:app --reload --port 8000
```

Проверка: `curl http://localhost:8000/health` → `{"status":"ok", ...}`.
Документация API — <http://localhost:8000/docs>.

При первом запуске скачиваются веса DINOv2 (~84 МБ). Если сети нет или
нужен быстрый прогон интерфейса — поднимите сервис в демо-режиме:
`DEMO_MODE=1 uvicorn backend.app.main:app --port 8000`.

### 2. Сайт

```bash
cd webapp
npm install
npm run dev          # http://localhost:5173
```

В dev-режиме сайт сам обращается к `http://localhost:8000`. Для продакшена
`npm run build` кладёт сборку в `webapp/dist`, и backend начинает раздавать
её сам — отдельный веб-сервер не нужен.

### 3. Telegram-бот

```bash
pip install -r bot/requirements.txt
# в .env: TELEGRAM_BOT_TOKEN (обязательно), GEMINI_API_KEY (для голосовых)
python bot/main.py
```

## API

| Метод | Путь | Что делает |
|---|---|---|
| `GET` | `/health` | статус сервиса и признак демо-режима |
| `POST` | `/predict/grain` | фото пробы зерна → доли, класс, цена, рекомендации |
| `POST` | `/predict/disease` | фото листа/растения → диагноз, меры, срочность |
| `GET` | `/docs` | интерактивная документация (Swagger) |

Оба эндпоинта принимают `multipart/form-data` с полем `file`
(JPEG/PNG/WebP/HEIC, до 12 МБ):

```bash
curl -X POST http://localhost:8000/predict/grain -F "file=@проба.jpg"
```

## Переменные окружения

Все настройки — в [`.env.example`](.env.example) с комментариями.

**Ключи никогда не хранятся в коде.** `GEMINI_API_KEY` и
`TELEGRAM_BOT_TOKEN` читаются из окружения: локально — из `.env` (он в
`.gitignore` и в `.dockerignore`), на хостинге — из панели Secrets /
Environment Variables. В репозитории лежат только пустые плейсхолдеры.

Цены пшеницы (`PRICE_CLASS_3_KZT` и соседние) вынесены в окружение
сознательно: рынок меняется, и подправить их надо уметь без пересборки.

## Что учитывать

- Это **предварительная оценка по внешнему виду зерна**. Официальная
  классность определяется лабораторно — клейковина, число падения, натура,
  влажность. Сервис это прямо пишет в каждом ответе и не притворяется
  лабораторией.
- Качество ответа зависит от съёмки: зерно — тонким слоем на контрастном
  фоне, сверху, при ровном свете; лист — крупным планом. Подсказки по съёмке
  встроены и в сайт, и в бота.
- На слабом CPU сервис разбирает не все найденные зёрна, а столько, сколько
  успевает за отведённое время, и сообщает об этом в ответе.

## Тесты

```bash
pip install -r requirements-dev.txt
pytest -q
```

Тестами закрыта та часть, где ошибка дороже всего — расчёт класса зерна и
экономики (пустая проба, партия ниже 5 класса, прибавка после очистки,
формат чисел) и полнота справочника мер: проверяется, что для каждого из
24 классов модели есть карточка «что это и что делать».

# Dän-AI — агроскан по фото

**AgriTech AI Hackathon, Трек 3 — компьютерное зрение в агрономии.**

> «Dän» (дән) — «зерно» по-казахски. Dän-AI = «зерновой ИИ».

**Карманный советник по партии зерна.**

Сегодня фермер либо сдаёт зерно вслепую, либо теряет деньги из-за неправильного
класса, либо платит за лабораторный анализ, когда менять что-то уже поздно. Ему
всю жизнь нужно было не «компьютерное зрение», а простой ответ прямо с телефона
на три вопроса:

1. **Какого примерно класса моя партия?**
2. **Сколько я из-за этого теряю в тенге?**
3. **Что мне сделать прямо сейчас?**

Dän-AI отвечает на все три за несколько секунд по одному фото: предварительный
класс, ориентир по деньгам за тонну и конкретное действие. Два входа в одну
систему: **сайт** и **Telegram-бот**.

---

## 1. Описание решения

Три функции в одном продукте:

1. **Качество зерна пшеницы (главный модуль).** По фото пробы: доли по категориям
   (целое здоровое / битое-повреждённое / щуплое-мелкое / проросшее / сорная
   примесь), предварительный класс, цена в тенге за тонну, потенциал после
   очистки и рекомендации — что сделать с партией и сколько это даст.
2. **Болезни, вредители и сорняки (24 класса).** По фото листа/растения: диагноз,
   что это, что делать, срочность и альтернативные версии. При низкой уверенности
   так и говорит, а не выдаёт случайный класс за факт.
3. **ИИ-консультант и голосовые.** Чат-консультант на сайте и в боте (Gemini);
   в Telegram можно задать вопрос **голосом на казахском или русском** — Gemini
   сам распознаёт речь и отвечает.

Система **сама определяет**, что на фото (зерно / растение / постороннее), —
пользователю не нужно выбирать модуль; чужое фото честно помечается как
нераспознанное, а не выдаётся за диагноз.

## 2. Стек технологий

| Слой | Технологии |
|---|---|
| **ML** | Замороженный **DINOv2 ViT-S/14** (готовые веса, без дообучения) → эмбеддинг 384 → голова-классификатор **LogisticRegression** (единственное, что обучалось) |
| **CV (модуль зерна)** | Классическая **OpenCV**-сегментация: Otsu по яркости/насыщенности, выбор маски по текстуре (лапласиан), watershed по локальным максимумам яркости |
| **Backend** | **FastAPI**, Uvicorn, PyTorch (CPU), scikit-learn, OpenCV, scikit-image |
| **Frontend** | **Vite + React + Tailwind + Framer Motion + React Three Fiber (Three.js)** — тёмный премиум-дизайн, 3D-hero |
| **Bot** | python-telegram-bot v21, httpx |
| **AI-сервисы** | **Google Gemini 2.5 Flash** — консультант и распознавание голосовых |
| **Деплой** | Docker (backend раздаёт и API, и собранный сайт); Colab + ngrok для быстрого запуска |

**Почему так:** за трое суток линейная голова поверх честно предобученного
DINOv2 даёт лучше и воспроизводимее, чем своя сеть с нуля. Обучается ровно один
слой (файл ~16–75 КБ, лежит в репозитории).

## 3. Инструкция по запуску

Нужен **Python 3.11+**. Node НЕ нужен — собранный сайт уже в репозитории, его
раздаёт backend. Датасеты для запуска прототипа НЕ нужны — обученные модели уже
в репозитории, а веса DINOv2 скачаются автоматически при первом запуске.

```bash
# 1. Склонировать
git clone https://github.com/sumomega-nexus137/D-n-AI
cd D-n-AI

# 2. Виртуальное окружение и зависимости
python -m venv .venv
source .venv/bin/activate         # Windows: .venv\Scripts\activate
pip install -r requirements.txt   # torch, fastapi, opencv... (~несколько минут)

# 3. Ключи (необязательно для анализа фото; нужны только для ИИ-консультанта)
cp .env.example .env              # открыть .env и вписать GEMINI_API_KEY

# 4. Запуск — backend отдаёт и API, и сайт
uvicorn backend.app.main:app --host 0.0.0.0 --port 8000
```

Открыть **http://localhost:8000** — откроется сайт, загрузите фото → получите
разбор. Документация API — http://localhost:8000/docs. При первом запросе
скачиваются веса DINOv2 (~84 МБ), дальше берутся из кэша.

**Telegram-бот** (отдельным процессом):

```bash
pip install -r bot/requirements.txt
# в .env: TELEGRAM_BOT_TOKEN (от @BotFather) и GEMINI_API_KEY (для голосовых)
python bot/main.py
```

**Запуск без своей машины (Colab + ngrok, бесплатно):** одна ячейка поднимает
сайт и бота — см. [`notebooks/run_backend_colab.py`](notebooks/run_backend_colab.py).
**Docker:** `docker build -t dnai . && docker run -p 7860:7860 dnai`. Подробности
деплоя — [`docs/DEPLOY.md`](docs/DEPLOY.md).

### Демо-режим без весов
`DEMO_MODE=1 uvicorn backend.app.main:app --port 8000` — поднимает сервис без
нейросети и отдаёт заготовленный ответ той же структуры (для проверки интерфейса).

## 4. Источники данных

Датасеты в репозиторий **не включены** (слишком большие). Для запуска прототипа
они не нужны — нужны только, если кто-то захочет **переобучить** модель. Ссылки:

**Модуль 1 — зерно:**
- [GrainSet](https://github.com/hellodfan/GrainSet) — 200K фото зерна пшеницы,
  Nature Scientific Data (2023), лицензия **CC BY 4.0**.

**Модуль 2 — болезни/вредители/сорняки:**
- [`kushagra3204/wheat-plant-diseases`](https://www.kaggle.com/datasets/kushagra3204/wheat-plant-diseases) (Kaggle, CC0) — болезни и вредители пшеницы.
- [`olyadgetch/wheat-leaf-dataset`](https://www.kaggle.com/datasets/olyadgetch/wheat-leaf-dataset) (Kaggle) — болезни листа пшеницы.
- [`vbookshelf/v2-plant-seedlings-dataset`](https://www.kaggle.com/datasets/vbookshelf/v2-plant-seedlings-dataset) (Kaggle, CC BY-SA 4.0) — сорняки (Plant Seedlings, Aarhus University).

Объёмы, таксономия и как источники сведены в общие классы —
[`docs/DATASETS.md`](docs/DATASETS.md). Код обучения — [`notebooks/`](notebooks/).

**Held-out тест — отдельный источник/сплит целиком**, а не перемешанная выборка.
Метрики: качество зерна — accuracy **98.8%**, macro-F1 0.988 (5 классов);
болезни/сорняки — accuracy **85.7%**, macro-F1 0.854 (24 класса). Подробности —
[`docs/TRAINING_RESULTS.md`](docs/TRAINING_RESULTS.md), проверка на реальных фото
с телефона (с честными ограничениями) — [`docs/REAL_WORLD_TEST.md`](docs/REAL_WORLD_TEST.md).

## Ограничения (честно)

- Это **предварительная оценка по внешнему виду**. Официальная классность —
  лабораторно (клейковина, число падения, натура, влажность). Сервис пишет это
  в каждом ответе.
- GrainSet снят промышленным сканером; на телефонных фото в других условиях
  освещения возможны смещения (например, завышение доли «битого»). Это ограничение
  прототипа, описанное в `docs/REAL_WORLD_TEST.md`, а не подделка результатов.
- На слабом CPU разбирается не всё зерно, а сколько успевается за отведённое
  время; об этом сообщается в ответе.
